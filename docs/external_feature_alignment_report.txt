TEMPORAL AND INTEGRITY CONTRACT
The supported stored-observation profile is feature_store 0.3.0: date precision, derived_at_cutoff, one source series. That existing profile requires availability == evaluation cutoff; the alignment primitive separately checks both conditions, including tests where they differ. Independently dated availability/evaluation storage requires an extension of the upstream observation contract, not an inferred conversion.

The phase reader verifies immutable references, policy approval, payload hashes, temporal indexes, source selection and a byte-computed semantic checksum. It scans temporal/series headers before decoding numerical observations. It decodes only the phase's eligible observations and the one immediately preceding prevailing state. Earlier superseded values and future Feature values are not handed to research. Exact selected PIT operands are verified by native row locators and hashes without decoding unrelated PIT values. Whole-payload checksums are integrity operations, not access to future numeric observations. Planning and UI may inspect materialization coverage metadata; P1 numerical execution receives only phase-safe values.

At each canonical prediction anchor, the latest state eligible under both temporal conditions is selected before validity/freshness is applied. Friday becomes Monday; earlier reference months cannot backdate availability. A newer invalid or null update supersedes the older state even if that older state was valid. Nothing is interpolated, backward-filled, changed to zero, reciprocated or sign-flipped.

MAX_AGE and EVENT_ONLY freshness behaviors are executable and tested, but are not selected by the initial installed Research Spec. MAX_AGE requires an explicit maximum, availability/evaluation age basis, calendar-day unit and inclusive/exclusive boundary. EVENT_ONLY permits only the first eligible canonical weekday and rejects collisions. New policies/profiles must explicitly pin different semantics; no numeric age threshold was invented.

The existing Target reader remains authoritative. Missing exact endpoint prices stay missing. Phase-crossing Target intervals remain excluded with the existing ENDPOINT_OUTSIDE_PHASE accounting; no future validation labels are supplied to discovery. P2 still requires exact plan/direction/horizon admission.

SUPPORTED BOUNDARY / REMAINING LIMITATIONS
- Another already-published external Feature conforming to the supported 0.3.0 observation, date availability, single-series, approved-policy and PIT-operand lineage contracts can use this alignment/Submit adapter without a provider-specific research branch.
- No CES ID, source symbol, monthly arithmetic or provider-specific calculation is embedded in the new alignment engine. The tests and read-only certification identify CES as the initial real example.
- Existing upstream Feature publication/full numerical retrieval currently specialize in a single monthly fractional-change calculation. Those older components were not generalized here. Publishing new kinds of Features/providers may require their own preparation/publisher extension; this task does not claim universal onboarding or publication support.
- Exactly one compatible stored materialization is required unless the profile explicitly pins one via external_materializations. Multiple captures are never silently ranked by file name or hash. Joining/stitching captures is not implemented.
- Timestamp/mixed-precision observations, unknown availability, unsupported lineage types, multi-source mappings, mixed series, ambiguous events, arbitrary custom orientation/construction, external universes and common-factor broadcasting are rejected, not inferred.
- Stored-schema validation is separate from alignment. Existing source evaluation and source availability policies still apply; date mapping does not repair unverified upstream timing.
- Only UNTIL_SUPERSEDED is installed for live UI use in this task; alternate supported freshness semantics require an explicit registered policy/profile.
- Archive dates and the following-weekday convention support retrospective research only. Exact dissemination time, certified historical decision-time eligibility, tradability and live readiness remain unverified. No production research, new timing certification or cloud deployment was performed.
